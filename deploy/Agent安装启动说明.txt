Agent 安装启动说明
==================

一、运行要求

1. 支持 macOS 或 Linux。
2. 系统需要已安装 Node.js 22 或更高版本。
3. 安装和运行必须使用同一个系统用户，不建议使用 root 用户启动。

二、安装目录

将 agent.tar.gz 复制到运行用户的主目录并解压：

cd ~
tar -xzf agent.tar.gz

也可以直接将构建产物中的 agent 目录完整复制到运行用户的主目录。最终结构为：

~/agent/
├── app/          程序运行文件，升级时可以整体替换
└── start.sh      启动及重启脚本，升级时可以替换

首次启动前不需要创建 data 目录，安装包中也不包含 data 目录。

三、首次启动

部署人员可在首次启动时通过环境变量注入技能中心地址：

export POWER_AGENT_SKILL_CENTER_URL="http://skillcenter.internal:3000"
export POWER_AGENT_SKILL_BOX_URL="http://skill-box.internal:3100"
export POWER_AGENT_SKILL_CENTER_CLIENT_ID="<技能中心分配的 Client ID>"
export POWER_AGENT_SKILL_CENTER_CLIENT_SECRET="<技能中心分配的 Client Secret>"
# 可选；默认请求 POWER_AGENT_SKILL_CENTER_URL/api/system/oauth2/token
export POWER_AGENT_SKILL_CENTER_TOKEN_URL="http://skillcenter.internal:3000/api/system/oauth2/token"
# 可选；默认 read write
export POWER_AGENT_SKILL_CENTER_SCOPE="read write"

POWER_AGENT_SKILL_CENTER_URL 用于查询技能列表，POWER_AGENT_SKILL_BOX_URL 用于下载解密以及安装、卸载数量上报。
技能中心启用鉴权时，Client ID 与 Client Secret 必须同时配置。Agent 会通过 OAuth2 Client Credentials 获取 Token，缓存到内存，并在调用技能列表接口时添加 Authorization: Bearer 请求头。Token 不会发送给盒子端下载和安装数量接口。
两个地址会写入 data/openclaw.json 的 skills.registry 配置，不在用户界面展示或允许用户修改。未配置技能中心地址时不会访问其他公共技能库。
对应服务与 Agent 同机部署时可使用 127.0.0.1；分机部署时必须填写 Agent 服务器能访问的局域网 IP 或域名。

执行：

cd ~/agent
chmod +x start.sh
./start.sh

首次启动会自动生成：

~/agent/data/
├── openclaw.json
├── auth/         用户账号和登录会话
├── users/        用户默认工作区和用户项目
├── agents/       Agent 运行及会话数据
├── extensions/   用户安装的插件
├── logs/         运行日志
├── media/        媒体文件
├── sandboxes/    沙箱数据
└── run/          进程状态文件

启动完成后，start.sh 会列出本机和当前所有局域网 IPv4 网卡的访问地址。例如：

http://127.0.0.1:18789
http://192.168.1.20:18789

本机可以使用 127.0.0.1；同一可信局域网中的其他电脑应使用运行 Agent 的服务器 IPv4 地址。Agent 默认监听所有 IPv4 接口，因此服务器有多个 IPv4 地址时可以同时通过这些地址访问。

首次进入页面时，系统会进入管理员初始化流程：

1. 设置管理员登录账号。
2. 设置管理员密码并确认密码。
3. 提交后使用刚创建的管理员账号登录。

首次启动会生成一个随机网关凭据并持久保存在 data/openclaw.json。用户完成本地账号登录后，页面会自动取得网关凭据，无需在“设置 > 连接”中手动填写；以后重启和升级会继续使用同一个凭据。

管理员是系统的首个用户，拥有用户管理权限。管理员后续创建的用户是否为管理员，以创建用户时选择的角色为准；普通用户不会自动获得管理员权限。

每个用户首次创建时，系统都会生成自己的默认工作区：

~/agent/data/users/<用户ID>/default

默认工作区用于“新增对话”和保存该用户的基础配置，它不是用户项目，因此不会显示在左侧“项目”列表中。

四、首次使用

1. 登录后打开“设置 > 模型”。
2. 添加模型服务商、模型 ID、API Base URL 和 API Key。
3. 先点击“保存”，再进行“测试文本对话”。
4. 测试成功后，将需要使用的模型设为默认主模型。
5. 点击左侧“新增对话”可直接使用当前用户的默认工作区进行对话。
6. 需要独立文件和上下文时，点击“项目”旁的“+”创建项目。
7. 打开左侧“技能”可搜索、筛选并安装技能中心中的技能。
8. 也可通过“导入技能包”上传包含 SKILL.md 的 ZIP 文件。
9. 技能按用户独立安装，一个用户安装的技能不会出现在其他用户中。

用户创建的项目保存在：

~/agent/data/users/<用户ID>/projects/<项目目录>

项目之间的工作区、文件和对话上下文相互独立。左侧“项目”区域只显示用户主动创建的项目，不显示系统默认工作区。

用户技能保存在：

~/agent/data/users/<用户ID>/skills/<技能目录>

用户的默认工作区和所有项目都会加载该用户的技能，升级 app 和 start.sh 不会删除这些数据。

五、后台运行

start.sh 会自动在后台启动 Agent，确认端口就绪后返回命令行，无需再使用 nohup 或 &。

直接执行：

cd ~/agent
./start.sh

正式部署时，现有更新程序只需在覆盖 app 和 start.sh 后执行 start.sh。

六、重启

直接再次执行 start.sh：

cd ~/agent
./start.sh

脚本会识别并停止当前 Agent 进程，然后启动新程序，不需要单独执行停止命令。

七、程序升级

升级程序只需要：

1. 用新版本覆盖 ~/agent/app 目录。
2. 用新版本覆盖 ~/agent/start.sh。
3. 保留 ~/agent/data 目录，不要覆盖或删除。
4. 执行 ~/agent/start.sh 完成重启。

升级包不应包含 data 目录。所有用户账号、项目、模型配置、插件和会话数据都保存在 data 目录中，升级 app 和 start.sh 不会影响用户数据。

八、日志与排查

主要运行日志：

~/agent/data/logs/openclaw.log

启动及网关标准输出日志：

~/agent/data/logs/start.log

如果端口 18789 被其他非 Agent 程序占用，需要先关闭占用程序，或者使用其他端口启动：

./start.sh --port 18790

start.sh 会按新端口重新生成并输出可用地址，例如：

http://127.0.0.1:18790
http://192.168.1.20:18790

九、网络与安全边界

1. 当前安装包面向网关与 Agent 部署在同一台机器、由多台客户端在可信局域网内共同使用的场景。
2. 服务会监听所有局域网接口。请使用系统防火墙限制 18789（或自定义端口）只允许可信网段访问，禁止直接映射到公网。
3. 普通 http://局域网IP 不是浏览器安全上下文，无法使用浏览器设备身份能力。为了支持可信局域网直接访问，本安装包显式采用共享网关凭据并关闭 Control UI 设备身份校验；本地用户登录仍然是进入应用的前置条件。
4. 当前本地账号用于登录、用户管理和工作目录划分，不是抵御恶意用户的强隔离边界。所有获准登录的本地用户都必须视为可信协作用户；不要给不可信人员创建账号。
5. 首个管理员尚未创建时，同一可信局域网内可访问该端口的客户端都能进入初始化流程。首次启动后应立即创建管理员，或先通过防火墙临时限制为仅部署人员可访问。
6. 如果需要跨不可信网络、互联网、彼此不信任的用户，或更严格的设备身份保护，应在 Agent 前部署 HTTPS 反向代理或使用 VPN，并采用不关闭设备身份校验的加固部署配置。仅开放端口或仅修改访问 IP 不能替代 HTTPS，也不能提供多租户强隔离。
7. data/openclaw.json 包含网关凭据及模型配置，应保持 data 目录权限为 0700，不要复制到安装包、代码仓库或公开日志中。
